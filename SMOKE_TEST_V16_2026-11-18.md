## Bugs found and fixed

**Real bugs in the V16 build: none found.** No change was made to
`src/v27.js`, `src/v27.css`, `build_v16.py`, or any other build file, and
`out/` was not regenerated.

**Harness bugs found in run 1 and fixed in `tools/v16/test27.js` only
(7 checks):**

1. H2/H3 "fight renders" — visibility was read **after** `close()` had
   cleared the fight DOM. Fixed: capture visibility right after the fight
   starts. (Hook data was correct in run 1 already.)
2. Plan-session per-answer XP — the driver's XP snapshot was taken **after**
   clicking "next", so the +20 plan bonus landed in the last answer's delta.
   Fixed: snapshot XP before advancing; the bonus is asserted separately in
   the session total.
3. Streak-7 summary gem — headless `innerText` drops the 💎 glyph. Root
   cause found by probing: the pre-existing V9 emoji→icon decorator swaps
   the literal 💎 for `<img src="assets/icons/v6/gem.png">` in the live DOM
   (applies to every layer, including V27). Fixed: accept the gem icon or
   the character.
4. J6 goal check — the completion goals live on the **Plan tab**
   (`renderPlan`), not the dashboard. Fixed: check the plan tab.
5. J10 "stored save still has no en27" — the seeder itself called
   `en27()`, creating it. Fixed: a `seedENJSNo27` variant that seeds SRS
   without touching `en27`.
6. §10 "gems 42" — see the achievements note below; the expectation was
   wrong, not the game.

## Notes on pre-existing behaviour (not V16 bugs)

- **Achievements grant +6 gems on a seeded fresh load.** Seeding XP 12500
  (= Lv 126) on a fresh save unlocks V7 achievements a4 "Cấp 5" and a5
  "Cấp 10" (+3 gems each) on the first load, once only — verified: gems
  42 → 48 with `ach: [a4, a5]`, stable on a second reload. This is the
  pre-existing V7 `checkAch()` behaviour (`wrap('gain', checkAch)`), not
  something V27 does. (V15.3's test24 saw 42 only because its save already
  had a4/a5 claimed from earlier steps.) The §10 check asserts XP 12500,
  gems 48, a4+a5 claimed.
- **V9 emoji→icon decorator** replaces emoji (💎, ⭐, …) with
  `assets/icons/v6/*.png` images in the live DOM. V27's gem line therefore
  renders as a gem icon, which is consistent with the "no emoji as main
  graphics" preference.
- **Build-script limitation (for the coordinator, not a V16 defect).**
  `build_v16.py` does **not** strip a previous v27 layer: it asserts the
  pristine V15.3 hash of `out/index.html` and refuses to run if any v27
  marker is present ("V27 layer already present — build_v16.py runs exactly
  ONCE"). If a v27 fix is ever needed, `out/` cannot be regenerated by
  re-running `build_v16.py`; it would need a v27-strip step or a fresh
  V15.3 tree. No fix was needed in this round, so this was verified by
  reading the script only — `build_v16.py` was never re-run, and neither
  were `build_v15ui.py` / `build_v15lib.py` / `build_v15nav.py`.

## What was NOT tested (with reasons)

- **Live Firebase login / cloud sync** — the Firebase SDK cannot reach the
  network from this sandbox, and no real Firebase project was configured
  for this run. Sync/login remain **NOT live-tested**; Anh must run the
  `FIREBASE_SETUP.md` live checklist against a real Firebase project before
  claiming sync/login work. (The merge *behaviour* was tested honestly in
  §9/J9 with `__v20sync.mergeSaves` on two local saves — it is
  last-write-wins for `en27` because the Q1 branch is deferred.)
- **Real phone touch** — all mobile checks are real-Chrome viewport,
  geometry and contrast measurements at 360/390/430 px, not touch input.
- **Safari** — Chrome 157 only; Safari-specific rendering is untested.
- **Google Fonts loading** — fonts are loaded from a CDN the sandbox cannot
  reach; the game was verified working with those requests failing (see the
  offline check, §9/J7). Whether the intended fonts render on a connected
  device was not verified here.
- **Speech audio by ear** — TTS calls (`speakEN`/`speakKO`, listen
  auto-speak) run without JS errors in headless Chrome, but no audio output
  was listened to; pronunciation quality/voice availability on a real
  device is untested.
- **Two-device sync over the network** — see Firebase above; only the local
  `mergeSaves` semantics were exercised.
