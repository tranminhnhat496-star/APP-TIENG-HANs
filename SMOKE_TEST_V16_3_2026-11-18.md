## 4. Bugs found during testing

**Real product bug — found during the build, FIXED (R-V31-F01-en18):**
`mergeBossMaps` (`v20_sync.js:120`) only read nested `{en,ko}` V19
records, so a two-device merge silently dropped every flat V18 boss
win (`v18.js:496` writes `{win:1,wins:1,at,item}`) — the boss id
survived as an empty `{}`. Fixed by merging flat records directly
(win OR, wins MAX, `at` latest, `item` kept). Covered by `test31.js`
§1 (7 new checks, all PASS on both runs). Not in the staged plan —
the plan had assumed the en18/en19 branch was already correct.

**Build-script bug — found during verification, FIXED:**
`build_v31.py` step-5 asserted `built.count("[V31] recordAnswer
dropped") == 2`, but the v31.js wrapper emits the warn through
`logWarn()`, which prepends `'[V31] '` at runtime — the literal
appears only once in source (the R-V31-F11 replacement). The assert
now counts the bare text `recordAnswer dropped` (×2: replacement +
wrapper). Verified: literal ×1, bare ×2 in the built file.

**Harness bugs — found on run 1, FIXED (no product impact):**
1. `test31.js` §1 crashed with `ReferenceError: merged is not
   defined` — `merged` is a harness-local const, not a vm global.
   Fixed by assigning `ctx.__merged = merged` and validating
   `__merged`. (Same class as the V16 harness's 7 run-1 bugs.)
2. §0 KO-entry check searched for the unescaped label `Quản lý dữ
   liệu & đồng bộ`, but the HTML source has it escaped as `&amp;`
   (count 0). Fixed to the escaped form; the entry is present ×1
   (`injectDataBtn`, `v20ko-btn`).
3. `package_v31.py`'s KO-entry check had the same unescaped-label
   bug (count 0 in the built file). Fixed to the escaped `&amp;` form
   during push prep, before any packaging run. No product impact.

**No other failures.** Run 1 before the fixes: 122 PASS / 1 FAIL
(KO label) + harness crash in §1; after the fixes run 1 and run 2
both: **123 PASS / 0 FAIL / 7 SKIP**.
